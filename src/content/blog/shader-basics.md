# 第 1 章 Shader 必备概念

## 第 1 节 渲染管线是什么

### 渲染管线概述

**什么是渲染管线？**

渲染管线（又称渲染流水线）是计算机图形学中，将三维场景转换为最终屏幕所见图像的过程。它由一系列阶段和操作组成，每个阶段负责特定的任务，逐步处理输入的几何数据、纹理信息，最终生成可视化图像。

> 一句话概括：渲染管线（流水线）就是**将数据分阶段的变为屏幕图像的过程**。

**渲染管线中的数据指什么？**

- **顶点数据**：模型的顶点坐标、法线向量、纹理坐标等
- **纹理数据**：纹理贴图等
- **光照数据**：光照参数、光源信息等
- 以及 Unity 场景上相关的其它数据

**渲染管线中的「分阶段」指什么？**

渲染管线分为 3 个阶段，每个阶段都对数据进行处理，最终在屏幕上呈现图像：

```
应用阶段  ──▶  几何阶段  ──▶  光栅化阶段
```

**总结**

渲染管线就是将数据分阶段的变为屏幕图像的过程。其中：

- **数据**：游戏场景中放置的模型、光源、摄像机等内容的数据
- **阶段**：应用阶段 → 几何阶段 → 光栅化阶段

通过这三个阶段对数据的处理，最终就能在屏幕上看见图像。注意：不同的渲染管线和图形 API 可能有不同的术语与具体实现细节。

---

### 应用阶段

**应用阶段主要做什么？**

应用阶段中大部分内容与渲染无关（如游戏逻辑处理、动画更新、物理模拟、场景管理等）。应用阶段完成后，后续的几何阶段与光栅化阶段才开始处理与图形渲染相关的数据和操作。

之所以把它归纳进渲染管线，是因为应用阶段为后续提供了最重要的内容——**数据**。应用阶段的主导者是 **CPU**，我们把渲染需要用到的数据传递给 GPU，供后两个阶段使用。

**应用阶段为渲染准备了什么？**

1. 把不可见的物体数据剔除（视锥剔除、遮挡剔除等）
2. 准备好模型相关数据（顶点、法线、切线、贴图、着色器……）
3. 将数据加载到显存中
4. 设置渲染状态（网格使用哪个着色器、材质、光源属性……）
5. 调用 **DrawCall**（CPU 通知 GPU 使用相关数据和渲染状态进行渲染）

**总结**

应用阶段主要是 CPU 主导的阶段，最核心的工作就是为后续渲染提供数据（顶点、法线、切线、纹理坐标、变换矩阵、材质属性等）。按 Unity 的规则做游戏开发即可，需要重点注意的是 **DrawCall 的优化**。

#### DrawCall

- 一次 DrawCall 就是 CPU 命令 GPU 进行渲染的命令
- 性能瓶颈主要在 CPU：每次调用 DrawCall 前，CPU 都要向 GPU 发送数据、状态、命令等大量内容
- DrawCall 过多时，CPU 会把大量时间花在提交 DrawCall 上，造成过载、卡顿

**如何减少 DrawCall？** 使用批处理（Batching）：

1. 合并网格（静态物体可合并网格）
2. 共用材质（不同网格之间共用一种材质）
3. 合并图集（2D 游戏和 UI 中，将多张图片合并为一张大图）

---

### 几何阶段

**知识必备：图元**

图元（Primitive）是几何数据的基本单元，是构成几何体的最小可绘制单元，可以是点、线、三角形。几何阶段会把顶点数据组合为图元，后续在光栅化阶段转换为像素。

**几何阶段主要做什么？**

几何阶段主要由 **GPU** 主导，我们没法完全控制，但 GPU 开放了部分控制权。主要工作是根据应用阶段输入的数据进行**顶点坐标变换**以及**裁剪不可见图元**。

具体过程：

- **顶点着色器**：完全可编程。处理来自 CPU 的每个顶点，主要工作有：
  - 坐标变换（顶点、法线、纹理坐标变换等）
  - 顶点属性处理（颜色、透明度、切线向量等，用于顶点动画、着色、光照）
  - 顶点插值（计算顶点属性的插值）
- **曲面细分着色器 / 几何着色器**：可选，需硬件与驱动支持，一般学习时不详讲
- **裁剪**：自动裁剪不在视野内 / 部分在视野内的图元，一般无需手动处理
- **屏幕映射**：将三维坐标系下的图元坐标转换到屏幕坐标系

**总结**

几何阶段主要是 GPU 主导的阶段，核心工作是对顶点处理、坐标变换、裁剪画面外图元，最终把模型顶点从**本地坐标**转换到**屏幕坐标**。我们主要通过自定义**顶点着色器**带来不同表现（如水波纹、布料等）。

---

### 光栅化阶段

**知识必备：像素与片元**

- **像素**：组成图像的最小可控单位，具有位置和属性（颜色等信息）。如 1920×1080 表示宽 1920、高 1080 个像素
- **片元**：光栅化阶段生成的像素 / 像素片段，是像素级操作的基本单位，每个片元代表屏幕上一个像素，并带有位置、颜色、深度值、法线等信息

**光栅化阶段主要做什么？**

光栅化阶段同样由 **GPU** 主导，主要工作是根据几何阶段输入的信息，计算每个图元覆盖哪些像素，并为这些像素计算颜色。

具体过程：

- **三角形设置**：计算三角形网格的边界表示数据（从顶点得到每条边的像素坐标表示）
- **三角形遍历**（扫描变换）：检查每个像素是否被三角形覆盖，覆盖则生成片元（含屏幕坐标、深度、法线……）
- **片元着色器**（像素着色器）：完全可编程。主要工作有：
  - 光照计算
  - 纹理映射（按片元在纹理中的位置采样，实现表面贴图）
  - 材质属性处理（颜色、透明度、反射率等）
  - 阴影计算
- **逐片元操作**（输出合并阶段）：可配置。主要工作有：
  - 决定片元可见性（深度测试、模板测试）
  - 通过测试后，把片元颜色与颜色缓冲区已有颜色合并（混合）

**总结**

光栅化阶段主要是 GPU 主导的阶段，核心工作是确定片元最终是否被渲染、以及最终渲染颜色。我们主要通过自定义**片元着色器**带来不同表现（逼真水面、火焰、黑白、模糊等）。

## 第 2 节 Shader 开发是什么

### Shader 是什么

Shader（中文：着色器）是一种用于描述如何渲染图形、计算图形外观的程序，用于控制图形的颜色、光照、纹理和其它视觉效果。它由着色器语言编写，提供了指令和语法来描述光照、纹理映射、阴影、反射等外观。

> 简而言之：Shader 就是用于编写图形表现效果的程序代码。而 **Shader 开发的本质**，就是对渲染管线中上一阶段传递过来的**数据**进行自定义处理，再传递给下一阶段，从而让图像最终以我们想要的方式显示。

### Shader 和渲染管线的关系

渲染管线是把数据分阶段的变为屏幕图像的过程；Shader 开发就是针对其中某些阶段的**自定义开发**，决定最终呈现效果。在 Unity 中，我们学习的 Shader 开发主要针对两个小阶段：

- **几何阶段 → 顶点着色器**
- **光栅化阶段 → 片元着色器**

## 第 3 节 其它相关必备概念

### 计算机图形程序接口

图形程序接口（Graphics API）是一套可编程的开放标准，本质上是软件而非硬件，是前辈写好的调用系统硬件（GPU）绘制图形的代码，可理解为显卡厂商定义的一系列底层图形加速 API。即使不学图形学也能用引擎开发游戏，但引擎本质是对图形接口的封装。

**必了解的图形程序接口：**

| 接口 | 简介 | 主要平台 |
| --- | --- | --- |
| **OpenGL** | 开放图形库，跨平台跨语言的底层图形库，应用极广 | 全平台 |
| **OpenGL ES** | 用于嵌入式系统，OpenGL 的子级（GLES2.0 / GLES3.0） | 安卓 / iOS |
| **Vulkan** | 下一代图形 API，对标 DX12，更底层灵活，可视为 OpenGL 升级版 | 全平台 |
| **DirectX（DX）** | 微软多媒体编程接口，不跨平台（D3D 对标 OpenGL） | Windows / Xbox |
| **WebGL** | 网页图形库，把 JS 与 OpenGL ES 2.0 结合，用于网页 3D | Web |
| **Metal** | 苹果自研图形技术，性能高但不跨平台 | iOS / macOS |

**对于我们的意义：** Unity 针对发布平台切换图形接口方案：

1. Windows 应用 → DX
2. 苹果电脑应用 → Metal
3. 移动平台应用 → OpenGL ES 或 Vulkan
4. 网页应用 → WebGL

我们平时用引擎开发不需要直接和图形接口打交道，但发布时常见的相关设置需要理解。

### Shader 开发相关必备概念

**渲染管线和图形接口程序的关系**

图形接口程序（OpenGL、DX 等）提供了对渲染管线的控制和管理功能，充当开发者与图形硬件之间的中间层，把开发者的渲染命令转化为硬件能执行的指令。

**Shader 和图形接口程序的关系**

Shader 属于图形接口程序的一部分。图形接口为 Shader 开发提供 API，并把 Shader 程序与渲染管线各阶段连接起来，把数据和指令传递给硬件（GPU）。

**不同图形接口程序对 Shader 开发的影响**

1. 使用的着色器语言不同：
   - OpenGL → GLSL；DX → HLSL；Metal → MSL；WebGL → GLSL ES
2. 坐标系原点不同：
   - OpenGL / WebGL / Metal：原点在屏幕**左下角**
   - DX：原点在屏幕**左上角**（DX12 可改为左下角）

## 第 2 节 数学基础——平移 / 缩放 / 旋转变换

### 矩阵的基本概念

**线性代数**研究线性方程、线性函数及其通过矩阵和向量空间的表达，图形学中强调矩阵与向量空间。可把向量想象成有大小方向的箭头。

**矩阵是什么？** 矩阵（Matrix）是线性代数中用于表示和处理数据的数学工具，方便进行向量计算、管理大量数据。一个 m×n 的矩阵由 m×n 个标量组成：

```text
Matrix =
[ M11  ⋯  M1n ]
[  ⋮   ⋱   ⋮  ]
[ Mm1  ⋯  Mmn ]
```

程序中常用：一维 / 二维数组、嵌套列表、引擎提供的矩阵结构（Unity 的 `Matrix4x4` 等）。

**为什么要学矩阵？** Shader 开发中大量数学计算（坐标系转换、投影、光照、纹理映射）都依赖矩阵。

### 矩阵乘法

**矩阵 × 标量：** 矩阵每个元素分别乘标量。

**矩阵 × 矩阵：**

1. 判断能否相乘：**左列数 = 右行数**
2. 结果结构：**左行数 × 右列数**
3. 标量相乘规则：**左行 × 右列再相加**

注意事项：

- 不满足交换律：`AB ≠ BA`
- 满足结合律：`(AB)C = A(BC)`

### 五个基本特殊矩阵

| 矩阵 | 说明 |
| --- | --- |
| **方块矩阵（方阵）** | 行列数相等（如 3×3、4×4） |
| **对角矩阵** | 只有主对角线有值，其余为 0 的方阵 |
| **单位矩阵** | 主对角线元素全为 1 的对角矩阵，`MI = IM = M` |
| **数量矩阵** | 主对角线元素为同一值的对角矩阵 |
| **转置矩阵** | 行与列互换，`(Mᵀ)ᵀ = M`，`(AB)ᵀ = BᵀAᵀ` |

### 逆矩阵

方阵 M 的逆记为 M⁻¹，满足 `MM⁻¹ = M⁻¹M = I`。存在逆矩阵则称可逆（非奇异），否则不可逆（奇异）。

**计算步骤：** 确认方阵 → 计算行列式（为 0 则无逆）→ 计算代数余子式矩阵 → 转置得到标准伴随矩阵 → 标准伴随矩阵 ÷ 行列式。

**重要性质：**

- `(M⁻¹)⁻¹ = M`
- `MM⁻¹ = M⁻¹M = I`
- `I⁻¹ = I`
- `(Mᵀ)⁻¹ = (M⁻¹)ᵀ`
- `(AB)⁻¹ = B⁻¹A⁻¹`；`(ABCD)⁻¹ = D⁻¹C⁻¹B⁻¹A⁻¹`
- `M⁻¹(Mv) = v`（逆矩阵可计算反向变换）

### 正交矩阵

方阵 M 满足 `MMᵀ = MᵀM = I` 即正交矩阵。由此推出：**正交矩阵的逆等于其转置，`Mᵀ = M⁻¹`**。

**判断方法：**

1. `MMᵀ = MᵀM = I`
2. 每一行（列）都是单位向量（`|v| = 1`）且彼此正交（`v·u = 0`）

**重要性质：** Mᵀ 也是正交矩阵；行列式为 1 或 -1；各行 / 各列都是单位向量且彼此正交。

### 行矩阵与列矩阵

Unity 中三维向量（x, y, z）用矩阵表示有两种：**列矩阵**（一列）与**行矩阵**（一行）。为统一算法，Unity 的 Shader 开发遵循标准线性代数：**向量表示为列矩阵进行计算**。

- 列矩阵：`CBAv = C(B(Av))`（从右到左：先 A 再 B 再 C 变换）
- 行矩阵需乘以变换矩阵的转置，结果才与列矩阵一致：`vAᵀBᵀCᵀ`

### 矩阵的几何意义

矩阵的几何意义就是**变换**，常见变换包含：平移、旋转、缩放。

- **线性变换**：保持直线平行性与原点位置（缩放、旋转）
- **仿射变换**：线性变换 + 平移（缩放、旋转后再平移）

### 齐次坐标

齐次坐标通过引入一个额外维度（n 维变 n+1 维，如 `(x, y, z)` → `(x, y, z, w)`）来方便几何变换：

1. **区分点和向量**：`w = 1` 表示点，`w = 0` 表示向量
2. **表达平移**：3×3 只能做线性变换（旋转、缩放），无法描述平移；引入齐次坐标得到 4×4 矩阵，3×3 称为线性矩阵，4×4 称为仿射矩阵

### 基础变换矩阵与三种变换

**构成规则：** 使用 4×4 仿射矩阵（旋转、缩放用 3×3 即可，统一用 4×4 只为方便）。

- **平移矩阵**：不是正交矩阵，逆矩阵固定且简单（直接取负平移分量）
- **旋转矩阵**：绕 x / y / z 轴旋转；是正交矩阵，逆 = 转置，可还原旋转。点（w=1）与向量（w=0）计算都会改变
- **缩放矩阵**：kx、ky、kz 为各轴缩放因子；通常不是正交矩阵（kx/ky/kz 非 1 时），逆矩阵有规律可循

### 复合运算

把平移、旋转、缩放组合起来形成复杂变换，即矩阵串联。因矩阵乘法不满足交换律，**顺序会影响结果**。

Unity 中约定：

1. 平移 / 旋转 / 缩放复合：**先缩放 → 再旋转 → 后平移**
2. x / y / z 轴旋转复合：**z → x → y**

```text
P新 = M平移 · M旋转 · M缩放 · P老
```

## 第 3 节 数学基础——坐标空间的变换

### 坐标空间是什么

坐标空间由基础参照物（原点）和相互垂直的轴线组成。三维空间用一个原点 + 三个坐标轴（x / y / z）描述点的位置。

渲染管线中，顶点 / 法线等模型数据会经历以下空间变换：

```
模型空间 → 世界空间 → 观察空间 → 裁剪空间 → 屏幕空间
```

之所以存在多种坐标空间，是因为不同问题需要不同坐标系方便解决。

### 坐标空间变换规则

**定义一个坐标空间需要：** 原点位置 + 3 个坐标轴方向。

**父子关系：** 在 Unity 中，世界坐标空间是大部分坐标空间的基础（父空间），其它多为子空间，形成层级结构。坐标空间变换本质是父 / 子空间之间对点 / 向量的变换：

- 子 → 父：可直接套用变换公式
- 父 → 子：需对公式取逆

**变换矩阵约定（子 S → 父 F）：**

```text
Af = M(s→f) · As        M(s→f) 为子到父的变换矩阵
Bs = M(f→s) · Bf        M(f→s) 是 M(s→f) 的逆矩阵
```

记忆规律：**子 → 父：先缩放，再旋转，最后平移；父 → 子：先平移，再旋转，最后缩放。**

### 模型空间变换

模型空间（Model Space，又称对象空间 / 局部空间）是模型的局部坐标系，每个模型独立，Z 轴通常朝模型正前方。Unity 用**左手坐标系**，模型空间的 x / y / z 对应模型的右 / 上 / 前。

**变换：** 模型空间 → 世界空间（典型子 → 父），即：

```text
世界坐标 = 平移矩阵 · 旋转矩阵 · 缩放矩阵 · 模型空间点 / 向量
```

有多个父对象时，逐层往上计算即可。

### 观察空间变换

观察空间（View Space，又称摄像机空间）可视为摄像机的模型空间，决定渲染视角与视野。注意：Unity 的观察空间遵循**右手坐标系**，x / y / z 正方向分别对应摄像机的右 / 上 / **后方**（与模型空间相反）。

**变换：** 世界空间 → 观察空间（父 → 子），对模型空间变换取逆即可。

### 齐次裁剪空间（裁剪空间）

**视锥体：** 摄像机可见区域的虚拟六面体，超出区域将被裁剪。透视投影下类似金字塔（远裁剪面更大，产生透视）；正交投影下为长方体（无透视）。

**裁剪空间（齐次裁剪空间）：** 坐标范围 (-1, -1, -1) 到 (1, 1, 1) 的规范化立方体，超出范围的坐标被裁掉。把视锥体投影到该立方体，可统一、便捷地进行裁剪。

#### 正交投影变换

目的：把正交投影视锥体（观察坐标系下）变换到齐次裁剪空间，分两步：

1. 把视锥体中心位移到观察空间原点
2. 把长方体 xyz 范围映射到 (-1, 1)（长宽高各为 2）的正方体

关键参数：`Size`（竖直方向高度的一半）、`Near` / `Far`（近 / 远裁剪面距离）、`Aspect`（宽高比）。

```text
近 / 远裁剪面高 = 2 · Size
近 / 远裁剪面宽 = Aspect · 2 · Size
```

#### 透视投影变换

目的：把透视投影视锥体变换到齐次裁剪空间，分三步：

1. 把透视视锥体挤压成长方体
2. 把长方体中心位移到观察空间原点
3. 把长方体 xyz 范围映射到 (-1, 1) 的正方体

关键参数：`FOV`（视锥开口角度）、`Near` / `Far`、`Aspect`。

```text
近裁剪面高 = 2 · Near · tan(FOV / 2)
远裁剪面高 = 2 · Far  · tan(FOV / 2)
近 / 远裁剪面宽 = Aspect · 对应高度
```

> 把观察空间顶点变换到裁剪空间的意义，就是让裁剪工作更通用便捷——不必针对每种视锥体单独处理。

### 屏幕空间变换

屏幕空间是渲染结果在屏幕上显示的坐标空间，对应真实像素位置。Unity 中：屏幕左下角为像素 (0, 0)，右上角为（分辨率宽，分辨率高）。

**变换：** 裁剪空间 → 屏幕空间（取 x / y 映射到屏幕，z 用于深度缓冲 / 深度测试）。

### 阶段总结

1. Shader 开发主要针对两个小阶段：**几何阶段 → 顶点着色器**，**光栅化阶段 → 片元着色器**
2. 数学基础已完成：用三角函数、向量、线性代数进行顶点 / 向量的矩阵变换
3. 顶点变换四步：**模型空间 → 世界空间 → 观察空间 → 裁剪空间 → 屏幕空间**（除观察空间为右手坐标系外，其余均为左手坐标系）
4. 顶点着色器基本任务：把顶点坐标从模型空间转换到裁剪空间；片元着色器可得到片元在屏幕空间的像素位置

> 注意：空间变换不仅针对顶点，切线、法线也需矩阵运算，其中**法线数据的变换规则略有不同**，留待后续讲解。

## 第 4 节 语法基础——ShaderLab 语法

### 材质和 Shader

- **Unity Shader vs Shader**：Shader 是通用概念；Unity Shader 是 Unity 中对底层渲染技术的封装，提供 **ShaderLab** 语言来编写管理着色器，可视为对 Shader 的封装
- **材质和 Shader 必须配合**：流程为 创建材质 → 创建 Unity Shader 并赋值给材质 → 把材质赋给渲染对象 → 在材质面板调参。Shader 提供的可编辑属性可直接在材质中改，无需改代码
- **创建材质**：Project 窗口右键 `Create → Material`
- **创建 Shader**：Project 窗口右键 `Create → Shader`，常用 `Unlit Shader`（不含光照，顶点 / 片元着色器模板）；另有 Standard Surface Shader、Image Effect、Compute、Ray Tracing 等

### ShaderLab 的基本结构

ShaderLab 是 Unity 自定义的语法规则，无论编写哪种 Shader 都会用它包装。基本由 4 部分组成：

```shaderlab
// 第一部分：名字（决定材质面板选择路径，建议不用中文、文件名与命名一致）
Shader "着色器名字"
{
    // 第二部分：属性（材质面板可见、可编辑，也可作为变量供子着色器使用）
    Properties
    {
        _Name("Display Name", type) = defaultValue[{options}]
    }

    // 第三部分：1~n 个子着色器
    SubShader
    {
        // 顶点-片段 / 表面 / 固定函数着色器
    }
    SubShader { /* 更精简版本，适配旧设备 */ }

    // 第四部分：备用 Shader
    Fallback "备用的Shader"
}
```

### ShaderLab 属性

基本语法：`_Name("Display Name", type) = defaultValue[{options}]`

- **数值类**：`Int`、`Float`、`Range(min,max)`（注意 Unity 中数值基本都是 Float，Int 编译时也会转 Float）
- **颜色 / 向量类**：`Color`、`Vector`（均为 4 分量，颜色 RGBA 取值 0~1，向量 XYZW 无限制）
- **纹理类**：`2D`、`2DArray`、`Cube`、`3D`，默认值可写 `white` / `black` / `gray` / `bump` / `red` 等，后接 `{}`

### SubShader 基本构成

SubShader 由 3 部分构成：**Tags（渲染标签）** / **States（渲染状态）** / **Pass（渲染通道）**。Unity 会从上到下选第一个能在当前显卡运行的 SubShader。每个 Pass 都会让物体多渲染一次，应尽量减少数量。

```shaderlab
SubShader
{
    Tags { "标签名" = "标签值" }   // 1. 渲染标签
    // 2. 渲染状态
    Pass { /* 渲染通道 */ }
    Pass { /* 可有多个 */ }
}
```

#### Tags 渲染标签（键值对，无数量限制）

- **Queue 渲染队列**（决定渲染顺序）：`Background`(1000)、`Geometry`(2000，默认)、`AlphaTest`(2450)、`Transparent`(3000)、`Overlay`(4000)；可自定义如 `Geometry+1`(2001)
- **RenderType 渲染类型**：用于着色器替换（相机 API 指定类型替换），如 `Opaque`、`Transparent`、`TransparentCutout`、`Background`、`Overlay` 等
- **DisableBatching**：`True` 禁用批处理（使用模型空间顶点数据的 Shader 需开启）
- **ForceNoShadowCasting**：`True` 不投射阴影
- **IgnoreProjector**：`True` 忽略投影机（半透明 Shader 常用）
- **CanUseSpriteAtlas** / **PreviewType**（Sprite 适配 / 预览形状）

> 以上标签只能在 SubShader 中声明；Pass 有自己专门的标签类型。

#### States 渲染状态

- **Cull**：`Back`（默认背面剔除）/ `Front`（正面剔除）/ `Off`（不剔除）
- **ZWrite**：`On`（默认写入深度）/ `Off`（透明等特殊效果常关）
- **ZTest**：`Less` / `Greater` / `LEqual`（默认）/ `GEqual` / `Equal` / `NotEqual` / `Always`
- **Blend**：如 `SrcAlpha OneMinusSrcAlpha`（正常透明）、`One One`（线性减淡）、`DstColor Zero`（正片叠底）等

> 状态可在 SubShader（影响所有 Pass）或 Pass（仅当前 Pass）中声明。

### Pass 渲染通道

```shaderlab
Pass
{
    Name "MyPass"          // 命名后可被 UsePass "路径/MYPASS" 复用（Unity 内部转大写）
    Tags { "LightMode" = "ForwardBase" }  // Pass 专属标签
    // 渲染状态
    // CG / HLSL 着色器代码
}
```

Pass 专属标签：`LightMode`（如 `Always`、`ForwardBase`、`ForwardAdd`、`Deferred`、`ShadowCaster` 等）、`RequireOptions`、`PassFlags`。此外可用 `GrabPass { "_BackgroundTexture" }` 抓取屏幕内容供后续 Pass 使用。

### 备用 Shader

当所有 SubShader 都无法运行时，`Fallback "Shader名"` 提供最低级 Shader 保底渲染；`Fallback Off` 则放弃保底。

### Shader 的编写形式

| 形式 | 位置 | 特点 |
| --- | --- | --- |
| **表面着色器** | SubShader 内 `CGPROGRAM…ENDCG` | 对顶点/片元着色器封装，代码少、可控性低、性能消耗高，适合 PC/主机、需复杂光照 |
| **顶点 / 片元着色器** | Pass 内 | 代码多但灵活、性能可控，移动平台首选，自定义效果多时优先 |
| **固定函数着色器** | Pass 内，用 ShaderLab 命令 | 已基本弃用，仅老设备，内部也会被编译为顶点/片元着色器 |

> 学习重点：**顶点 / 片元着色器**。

## 第 5 节 语法基础——CG 语法

### CG 语句写在哪里

顶点 / 片元着色器的 CG 代码写在 Pass 内：

```hlsl
CGPROGRAM
    // 这里写 CG 代码
ENDCG
```

通过 `#pragma` 指定着色器函数：

```hlsl
#pragma vertex   顶点着色器函数名
#pragma fragment 片元着色器函数名
```

### CG 基础数据类型

| 类型 | 说明 |
| --- | --- |
| `int` / `uint` | 32 位整型 / 无符号整型 |
| `float` | 32 位浮点（符号 f） |
| `half` | 16 位浮点（符号 h） |
| `fixed` | 12 位浮点 |
| `bool` | 布尔 |
| `string` | 字符串 |
| `sampler` / `sampler1D` / `sampler2D` / `sampler3D` / `samplerCUBE` / `samplerRECT` | 纹理采样器（按维度 / 类型区分） |

复合类型：数组声明与 C# 类似，但 CG **无法直接获取数组长度**，建议单独声明长度变量；结构体与 C# 类似（无访问修饰符，声明结束加分号，一般函数外声明）。

### CG 特殊数据类型

- **向量**：内置类型，最大 4 维，如 `float3(n1,n2,n3)`、`float4(n1,n2,n3,n4)`
- **矩阵**：最大 4×4，最小 1×1，如 `float4x4`、`float3x3`
- **bool 向量**：可存储比较结果，如 `bool3 c = a < b;`

> 向量 / 矩阵是内置数据类型，数组是数据结构，二者不同。

### Swizzle 操作符

用点号获取 / 重排向量分量，支持 `.xyzw`（坐标）与 `.rgba`（颜色）：

```hlsl
fixed4 f4 = fixed4(1, 2, 3, 4);
fixed f = f4.w;     // 提取分量
f4 = f4.yzxw;       // 重排分量
fixed3 f3 = f4.xyz; // 生成新向量
```

矩阵按二维数组方式取元素：`f4x4[0][0]`；可用向量取某一行：`fixed4 row = f4x4[3]`；高维可用低维容器装载（自动舍多余，如 `float3x3 m = f4x4;`）。

### 运算符

- 比较（`> < >= <= == !=`）、条件（`?:`）、逻辑（`|| && !`，注意 CG **无短路**）、数学（`+ - * / % ++ --`，注意 **取余只能用于整数**）——均与 C# 一致

### 流程控制

`if` / `switch` / `for` / `while` / `do while` 与 C# 一致。需注意性能：尽量少用循环、利用 GPU 并行性替代、避免复杂条件分支。

### 函数

```hlsl
void name(in 类型 参数, out 类型 参数) { }   // 无返回值，in 输入 / out 输出
类型 name(in 类型 参数) { return 值; }          // 有返回值
```

`in`：外部传给内部，内部只使用不改；`out`：内部初始化 / 修改后传回外部。建议显式写 `in` / `out` 提高可读性。顶点 / 片元着色器函数只用单返回值。

### 顶点 / 片元着色器基本结构

```hlsl
#pragma vertex   myVert
#pragma fragment myFrag

// 顶点着色器：POSITION 语义把模型顶点坐标填入 v；SV_POSITION 表示输出裁剪空间坐标
float4 myVert(float4 v : POSITION) : SV_POSITION
{
    return UnityObjectToClipPos(v);   // 等价于 mul(UNITY_MATRIX_MVP, v)
}

// 片元着色器：SV_Target 表示输出到默认帧缓存
fixed4 myFrag() : SV_Target
{
    return fixed4(0, 1, 0, 1);
}
```

**语义（Semantics）**：用于标记着色器输入 / 输出变量的用途，确保管线正确处理数据。获取更多数据时，用**结构体封装**成员变量并加语义；片元着色器数据基本来自顶点着色器，所以该结构体还要作为顶点着色器返回值类型。

> 只有顶点 / 片元着色器回调函数的参数与返回值需要语义修饰，自定义函数不需要。

### ShaderLab 属性与 CG 变量类型匹配

| ShaderLab 属性 | CG 变量类型 |
| --- | --- |
| `Color`, `Vector` | `float4` / `half4` / `fixed4` |
| `Range`, `Float`, `Int` | `float` / `half` / `fixed` |
| `2D` | `sampler2D` |
| `Cube` | `samplerCUBE` |
| `3D` | `sampler3D` |
| `2DArray` | `sampler2DArray` |

在 CG 语句块中声明与属性**同名**变量即可直接使用。

### CG 内置函数（常用）

- **数学**：`abs` `ceil` `floor` `clamp(x,a,b)` `max` `min` `sqrt` `pow` `lerp(a,b,f)` `saturate(x)` `step(a,x)` `smoothstep` `round` `radians` `degrees` `sin` `cos` `tan` `asin` `acos` `atan` `atan2` `exp` `log` `sign` 等
- **向量 / 矩阵**：`dot(A,B)` `cross(A,B)`（均须三维）`mul(M,N)` `mul(M,v)` `mul(v,M)` `transpose(M)` `determinant(M)`
- **几何**：`length(v)` `normalize(v)` `distance(p1,p2)` `reflect(I,N)` `refract(I,N,eta)`
- **纹理**：`tex2D(sampler2D, float2)`、`texCUBE(samplerCUBE, float3)` 等，返回值均为 `fixed4` 颜色

### CG 内置文件

位于 Unity 安装目录 `Editor/Data/CGIncludes`，`.cginc` 为 CG 内置文件。常用：

- `UnityCG.cginc`：最常用帮助函数、宏、结构体
- `Lighting.cginc`：内置光照模型（Surface Shader 自动包含）
- `UnityShaderVariables.cginc`：全局变量（自动包含）
- `HLSLSupport.cginc`：跨平台宏与定义（自动包含）

使用时在 CG 块内 `#include "UnityCG.cginc"`。常用内容：

- **方法**：`WorldSpaceViewDir` `ObjSpaceViewDir` `WorldSpaceLightDir` `UnityObjectToWorldNormal` `UnityObjectToWorldDir` 等
- **结构体**：`appdata_base` `appdata_tan` `appdata_full` `appdata_img` `v2f_img`
- **变换矩阵宏**：`UNITY_MATRIX_MVP`（模型→裁剪）、`UNITY_MATRIX_MV`、`UNITY_MATRIX_V`、`UNITY_MATRIX_P`、`UNITY_MATRIX_VP`、`_Object2World`、`_World2Object` 等
- **变量**：`_Time`（动画用）、`_LightColor0` 等

> 参考：内置文件 / 函数 / 宏 / 变量 详见 Unity 官方文档（SL-BuiltinIncludes / SL-BuiltinFunctions / SL-BuiltinMacros / SL-UnityShaderVariables），CG 内置函数与 HLSL 类似（非全部 Unity 都支持）。
