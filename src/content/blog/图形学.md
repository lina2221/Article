### **<font style="color:rgb(25, 27, 31);">点乘在图形学的应用</font>**
<font style="color:rgb(25, 27, 31);">AB=|A||B|cosθ</font>

+ <font style="color:rgb(25, 27, 31);">点乘主要应用于求两个单位向量的夹角，</font>
+ <font style="color:rgb(25, 27, 31);">观察两个向量之间是同向、垂直还是反向，可以观察两个向量的接近，若两个向量的点乘接近1则离得很近，若接近0则离得很远</font>
+ <font style="color:rgb(25, 27, 31);">利用投影可将一个向量分解成两个（多个）向量和</font>

### **<font style="color:rgb(25, 27, 31);">叉乘在图形学的应用</font>**
+ <font style="color:rgb(25, 27, 31);">AxB=-BxA</font>
+ <font style="color:rgb(25, 27, 31);">判定左右（内外）</font>
    - <font style="color:rgb(25, 27, 31);">若AxB为正则点A在点B在A左侧，若点P在点A、B、C内，则ABXAP，BCxBP,CAxCP结果都为外（内）则P在ABC内</font>
    - <font style="color:rgb(25, 27, 31);">若任意一个结果不同则P在ABC外</font>
+ <font style="color:rgb(25, 27, 31);">定义坐标系</font>
    - <font style="color:rgb(25, 27, 31);">要求：单位向量、互相垂直（点乘为0且叉乘结果为另外一轴）</font>
    - <font style="color:rgb(25, 27, 31);">可以获得任意一个向量分解为多个投影</font>

### **<font style="color:rgb(25, 27, 31);">矩阵知识点</font>**
+ <font style="color:rgb(25, 27, 31);">（MxN）（NxP）=（MxP）</font>
+ <font style="color:rgb(25, 27, 31);">矩阵</font>**<font style="color:rgb(25, 27, 31);">没有</font>**<font style="color:rgb(25, 27, 31);">交换律，只有结合律</font>
+ <font style="color:rgb(25, 27, 31);">转置：(AB)T=BT AT</font>
+ <font style="color:rgb(25, 27, 31);">单位矩阵I（对角阵I）：可以算出矩阵A-1(A逆)，可以用于返回变换前的结果</font>
+ <font style="color:rgb(25, 27, 31);">向量的点乘、叉乘都可以转换为矩阵相乘</font>
+ <font style="color:rgb(25, 27, 31);">点乘：A·B=ATB</font>
+ <font style="color:rgb(25, 27, 31);">叉乘：AxB=A*B</font>

```glsl
uniform sampler2D myTexture; // 获取纹理 uniform是全局变量
uniform vec3 lightDir; //获取光照方向
varying vec2 uv;//获取uv坐标
varying vec3 norm; //获取法线坐标
void diffuseShader()
{
    vec3 kd;//获取kd系数
    kd = texture2d(myTexture, uv); 
    kd *= clamp(dot(–lightDir, norm), 0.0, 1.0); //Phong模型漫反射
    gl_FragColor = vec4(kd, 1.0); //输出该像素的颜色
}
```

### **<font style="color:rgb(25, 27, 31);">德卡斯特里奥算法</font>**
<font style="color:rgb(25, 27, 31);">通过德卡斯特里奥算法法来绘制贝塞尔曲线。</font>

+ <font style="color:rgb(25, 27, 31);">引入参数t（范围 为0-1）</font>
+ <font style="color:rgb(25, 27, 31);">取b0到b1，b1到b2上t位置的点b0‘，b1’</font>
+ <font style="color:rgb(25, 27, 31);">将b0‘，b1’连接</font>
+ <font style="color:rgb(25, 27, 31);">取b0‘到b1’t位置上的带你b0‘’</font>
+ <font style="color:rgb(25, 27, 31);">将所有的0-1所有的b0‘’点都遍历一份相连即可得到贝塞尔曲线</font>
+ <font style="color:rgb(25, 27, 31);">若有n个控制点则将上面步骤进行递归操作直到找到最终位移b0n</font>

### **<font style="color:rgb(25, 27, 31);">阴影映射（Shadows mapping）</font>**
### **<font style="color:rgb(25, 27, 31);">基本流程</font>**
+ <font style="color:rgb(25, 27, 31);">从光源看向场景并做深度测试</font>
+ <font style="color:rgb(25, 27, 31);">从视锥体位置看向场景，从场景中看到的点投影回光源得到该点在深度图中的位置</font>
    - <font style="color:rgb(25, 27, 31);">有些点可以被视锥体看到也可以被光源看到（视锥体投影到的深度图与光源中的深度图相同）</font>
    - <font style="color:rgb(25, 27, 31);">有些点可以被视锥体看到但</font>**<font style="color:rgb(25, 27, 31);">不能</font>**<font style="color:rgb(25, 27, 31);">被光源看到（视锥体投影到的深度图与光源中的深度图</font>**<font style="color:rgb(25, 27, 31);">不符</font>**<font style="color:rgb(25, 27, 31);">）</font>
+ <font style="color:rgb(25, 27, 31);">不能被光源看到的位置但可以被视锥体看到的位置就是阴影的位置</font>

### **<font style="color:rgb(25, 27, 31);">出现的问题</font>**
+ <font style="color:rgb(25, 27, 31);">只能做硬阴影不能做软阴影（目前以及有技术可以做到）</font>
+ <font style="color:rgb(25, 27, 31);">由于shadow map的分辨率问题，阴影可能出现锯齿</font>
+ <font style="color:rgb(25, 27, 31);">浮点精度问题，可能在是否能同时被视锥体与光源看到的界定上出现问题引发误差</font>

### **<font style="color:rgb(25, 27, 31);">轴对齐包围盒(AABB)</font>**
### **<font style="color:rgb(25, 27, 31);">特殊的包围盒定义</font>**
<font style="color:rgb(25, 27, 31);">三对面的交集形成的立方体，三对面分别于xyz轴平行</font>

<font style="color:rgb(25, 27, 31);">使用包围盒包围与光一定轴对齐，减少了计算量</font>

<font style="color:rgb(25, 27, 31);">需要3次减法，6次乘法和1次除法。</font>

<u><font style="color:rgb(25, 27, 31);">AABB中：</font></u>

<font style="color:rgb(25, 27, 31);">每一个轴只需要一次除法和一次减法，一共只需要3次减法和三次除法</font>

<u><font style="color:rgb(25, 27, 31);">八叉树：</font></u>

+ <font style="color:rgb(25, 27, 31);">八叉树是在每个子树下面画十字，划分为四块（在二维下是分为四块，三维是八块）</font>
+ <font style="color:rgb(25, 27, 31);">由于是均匀划分，会出现将同一个物体划分为两块的问题。</font>

### **<font style="color:rgb(25, 27, 31);">层次包围盒（BVH）</font>**
<u><font style="color:rgb(25, 27, 31);">BVH的特点：</font></u>

+ <font style="color:rgb(25, 27, 31);">按照三角形进行划分，因此一个物体只可能出现在一个包围盒内</font>
+ <font style="color:rgb(25, 27, 31);">由于按照三角形进行划分，因此不会出现那一判断包围盒边界的问题</font>
+ <font style="color:rgb(25, 27, 31);">BVH的思想更像分组，只需将三角形进行分组并对三角形较多的组进行递归分组</font>
+ <font style="color:rgb(25, 27, 31);">每次的划分都选择XYZ中最长的轴进行划分，这样保证划分的大小比较平均</font>
+ <font style="color:rgb(25, 27, 31);">总是选择中间的三角形进行划分，这样划分出来树更加接近平衡二叉树</font>
+ <font style="color:rgb(25, 27, 31);">划分到一个比较小的数量后停止划分（比如5个三角形）</font>

<!-- 这是一张图片，ocr 内容为： -->
![](/graphics/img_096.png)

<u><font style="color:rgb(25, 27, 31);">BVH的伪代码：</font></u>

```glsl
Intersect(Ray ray, BVH node) 
{
    if (ray misses node.bbox) 
        return;//如果与节点光线都不相交就返回
    if (node is a leaf node)//如果相交且这是一个叶子节点
    {
        test intersection with all objs;//将节点内三角形都做判断
        return closest intersection;//返回最近的那个
    }
    hit1 = Intersect(ray, node.child1);//如果不是叶子节点则递归找到最近的那个
    hit2 = Intersect(ray, node.child2);
    return the closer of hit1, hit2;
}
```

### **<font style="color:rgb(25, 27, 31);">直接光照的算法</font>**
```glsl
shade(p, wo)
    Randomly choose N directions wi~pdf
    Lo = 0.0
    For each wi
        Trace a ray r(p, wi)
        If ray r hit the light
            Lo += (1 / N) * L_i * f_r * cosine / pdf(wi)
    Return Lo
```

### **<font style="color:rgb(25, 27, 31);">全局光照的算法</font>**
```glsl
shade(p, wo)
    Randomly choose N directions wi~pdf
    Lo = 0.0
    For each wi
        Trace a ray r(p, wi)
        If ray r hit the light
            Lo += (1 / N) * L_i * f_r * cosine / pdf(wi)
        Else If ray r hit an object at q
            Lo += (1 / N) * shade(q, -wi) * f_r * cosine / pdf(wi)
    Return Lo
```

<font style="color:rgb(25, 27, 31);">如果采样中反射过来的不是光源而是物体则将物体也当做光源，将物体反射过来的能量来进行计算。</font>

```glsl
        Return L_i * f_r * cosine / pdf(wi)
    Else If ray r hit an object at q

```

<font style="color:rgb(25, 27, 31);">只采样一次的光线追踪被称之为路径追踪，上面采样N次的被称之为分布式光线追踪（Distributed Ray Tracing）</font>

<font style="color:rgb(25, 27, 31);">对于每个像素发射N条光线（采样）做以下的算法</font>

<font style="color:rgb(25, 27, 31);">将每个射出去的采样接收到能量的点做蒙特卡洛积分得到平均值</font>

```glsl
ray_generation(camPos, pixel)
    Uniformly choose N sample positions within the pixel
    pixel_radiance = 0.0
    For each sample in the pixel
        Shoot a ray r(camPos, cam_to_sample)
        If ray r hit the scene at p
            pixel_radiance += 1 / N * shade(p, sample_to_cam)
    Return pixel_radiance
```

### **<font style="color:rgb(25, 27, 31);">由于路径追踪递归产生的死循环</font>**
+ <font style="color:rgb(25, 27, 31);">首先增加一个结束的概率P_RR</font>
+ <font style="color:rgb(25, 27, 31);">每次调用shade函数的时候做一个随机数判断</font>
+ <font style="color:rgb(25, 27, 31);">若大于随机数则return0反之继续执行shade函数并返回L0/P_RR</font>
+ <font style="color:rgb(25, 27, 31);">这样算下来数学期望不会变，E(L0)=P∗(L0/P)+(1−P)∗0=Lo</font>
+ <font style="color:rgb(25, 27, 31);">且路径追踪总会停下来</font>

```glsl
shade(p, wo)
    Manually specify a probability P_RR
    Randomly select ksi in a uniform dist. in [0, 1]
    If (ksi > P_RR) return 0.0;
    
    Randomly choose ONE direction wi~pdf(w)
    Trace a ray r(p, wi)
    If ray r hit the light
        Return L_i * f_r * cosine / pdf(wi) / P_RR
    Else If ray r hit an object at q
        Return shade(q, -wi) * f_r * cosine / pdf(wi) / P_RR
```

```glsl
    # 光源的直接光照
    L_dir = 0.0
    Uniformly sample the light at x’ (pdf_light = 1 / A)
    Shoot a ray from p to x’
    If the ray is not blocked in the middle
        L_dir = L_i * f_r * cos θ * cos θ’ / |x’ - p|^2 / pdf_light
    # 光源对其他物体的弹射
    L_indir = 0.0
    Test Russian Roulette with probability P_RR
    Uniformly sample the hemisphere toward wi (pdf_hemi = 1 / 2pi)
    Trace a ray r(p, wi)
    If ray r hit a non-emitting object at q
        L_indir = shade(q, -wi) * f_r * cos θ / pdf_hemi / P_RR
    Return L_dir + L_indir
```

## **<font style="color:rgb(25, 27, 31);">高级图形渲染概要</font>**
### **<font style="color:rgb(25, 27, 31);">高级光线传播</font>**
+ <font style="color:rgb(25, 27, 31);">无偏光线传播</font>
    - <font style="color:rgb(25, 27, 31);">双向路径追踪（BDPT）</font>
    - <font style="color:rgb(25, 27, 31);">Metropolis光线传播 (MLT)</font>
+ <font style="color:rgb(25, 27, 31);">有偏光线传播</font>
    - <font style="color:rgb(25, 27, 31);">光子映射</font>
    - <font style="color:rgb(25, 27, 31);">Vertex connection and merging (VCM) -结合双向追踪和光子映射</font>
+ <font style="color:rgb(25, 27, 31);">实时辐射度算法（IR）</font>

<font style="color:rgb(25, 27, 31);">有偏是随着样本的增加，结果会变化，如果样本无限多，结果会收敛到正确值。</font>

<font style="color:rgb(25, 27, 31);">无偏是不管样本有多少，都会得到正确的结果。</font>

<font style="color:rgb(25, 27, 31);">只要得出的结果会模糊就是有偏。</font>

### **<font style="color:rgb(25, 27, 31);">双向路径追踪（BDPT）</font>**
<font style="color:rgb(25, 27, 31);">思想：从光源和相机各打出一条光线，然后连接端点。</font>

<font style="color:rgb(25, 27, 31);">应用场景：在光源由漫反射形成的场景中效果较好。</font>

### **<font style="color:rgb(25, 27, 31);">Metropolis光线传播 (MLT)</font>**
<font style="color:rgb(25, 27, 31);">思想：使用马尔科夫链和蒙特卡罗方法，通过一定的概率扰动路径的传播，得到一条新的路径，由一条路径追踪为种子生成其他的路径。</font>

<font style="color:rgb(25, 27, 31);">应用场景：在复杂场景中的光线追踪</font>

<font style="color:rgb(25, 27, 31);">缺点：难以估计渲染完成画面的时间，局部的结果可能会比较"脏"</font>

### **<font style="color:rgb(25, 27, 31);">光子映射</font>**
<font style="color:rgb(25, 27, 31);">应用场景：特别适合渲染水中焦散的现象</font>

<font style="color:rgb(25, 27, 31);">一种实现方法之一：</font>

+ <font style="color:rgb(25, 27, 31);">从光源打出光线，在路径中发生反射折射，直到打到漫反射的物体上停止</font>
+ <font style="color:rgb(25, 27, 31);">再从相机打出光线，在路径中发生反射折射，直到打到漫反射的物体上停止</font>
+ <font style="color:rgb(25, 27, 31);">做局部的密度估计，对任意一个着色点取他周围的确定光子数并通过其占据的面积计算密度</font>

<font style="color:rgb(25, 27, 31);">缺点：如果当光子取值，画面会很脏，如果光子取值很大，画面会变糊。</font>

<font style="color:rgb(25, 27, 31);">如果光子数量无限多，那么就可以收敛成正确的画面。</font>

### **<font style="color:rgb(25, 27, 31);">Vertex connection and merging (VCM)</font>**
<font style="color:rgb(25, 27, 31);">思想：结合光子映射和双向路径追踪，如果BDPT中两边打出的光线不能连接，利用光子映射将一定范围的光线做融合，提高光线利用率。</font>

### **<font style="color:rgb(25, 27, 31);">实时辐射度算法（IR）</font>**
<font style="color:rgb(25, 27, 31);">思想：光源先进行若干次弹射到某个物体上，将这些物体当做是新的光源再进行路径追踪。</font>

<font style="color:rgb(25, 27, 31);">优点：渲染速度快，对漫反射场景效果较好。</font>

<font style="color:rgb(25, 27, 31);">缺点：无法处理glossy材质且场景缝隙会产生亮点。</font>

### **<font style="color:rgb(25, 27, 31);">材质建模</font>**
### **<font style="color:rgb(25, 27, 31);">非表面模型</font>**
<u><font style="color:rgb(25, 27, 31);">散射介质</font></u><font style="color:rgb(25, 27, 31);">：光在传播时穿过会发生散射的介质比如雾、云等，通过相位函数决定了光如何被散射。</font>

<font style="color:rgb(25, 27, 31);">光通过散射介质的两种情况：</font>

+ <font style="color:rgb(25, 27, 31);">被吸收一部分能量，被介质削减了一部分能量</font>
+ <font style="color:rgb(25, 27, 31);">被反射一部分能量，能量从其他地方的能量照射进来或者介质本身会发光</font>

<u><font style="color:rgb(25, 27, 31);">头发/毛发</font></u><font style="color:rgb(25, 27, 31);">：毛发可以理解为一个柱状模型，可以直接反射，也可以发生折射进入内部。</font>

<font style="color:rgb(25, 27, 31);">介绍了几种模型：</font>

+ <font style="color:rgb(25, 27, 31);">Kajiya-Kay Model：认为头发只有反射没有折射</font>
+ <font style="color:rgb(25, 27, 31);">Marschner Model：认为头发是一个半透明的玻璃圆柱体，有反射也有折射</font>
+ <font style="color:rgb(25, 27, 31);">Double Cylinder Model：动物与人类的头发不同，动物的头发髓质很大因此更容易发生散射，所以需要重新考虑模型，增加了散射这一参考系</font>

<u><font style="color:rgb(25, 27, 31);">颗粒材质</font></u><font style="color:rgb(25, 27, 31);">：可以制作出比如沙子城堡的材质</font>

### **<font style="color:rgb(25, 27, 31);">表面细节</font>**
+ <font style="color:rgb(25, 27, 31);">渲染出来的场景太过于完美，反而没那么真实，真实的世界有磨损有划痕。</font>
+ <font style="color:rgb(25, 27, 31);">微表面模型的BRDF的法线分布不该是均匀的，满足大体趋势的同时有自己的波动，但是会造成运算量巨大。</font>
+ <font style="color:rgb(25, 27, 31);">这是因为在法线分布复杂的情况下，很难建立有效的的光线通路（光源→表面→摄像机）</font>
+ <font style="color:rgb(25, 27, 31);">通过一个像素对应了一块表面，把整块范围内的法线分布整合起来获得（P-NDF），以此简化计算</font>
+ <font style="color:rgb(25, 27, 31);">如果表面足够微小，需要考虑波粒二象性使用波动光学，传统的几何光学反而不太够用了。</font>
+ <font style="color:rgb(25, 27, 31);">使用波动光学得到的BRDF和几何光学得到的BRDF类似又有自己的特点（光的干涉和衍射）</font>

### **<font style="color:rgb(25, 27, 31);">程序化生成</font>**

+ <font style="color:rgb(25, 27, 31);">通过查询的方法可以生成各种各样的模型</font>
+ <font style="color:rgb(25, 27, 31);">工业界使用Houdini专门来做程序化生成材质</font>

## **<font style="color:rgb(25, 27, 31);">照相机、镜头和光场</font>**
### **<font style="color:rgb(25, 27, 31);">成像</font>**
+ <font style="color:rgb(25, 27, 31);">成像 = 合成+捕捉</font>
+ <font style="color:rgb(25, 27, 31);">最早的相机是通过小孔成像的原理来成像的，现在的针孔相机也是使用这个原理</font>
+ <font style="color:rgb(25, 27, 31);">快门控制光能在相机中待多长时间</font>
+ <font style="color:rgb(25, 27, 31);">传感器（Sensor）记录的是光的Irradiance信息</font>
+ <font style="color:rgb(25, 27, 31);">针孔摄像机没有透镜，因此做不成景深</font>

### **<font style="color:rgb(25, 27, 31);">视场(FOV)</font>**
+ <font style="color:rgb(25, 27, 31);">FOV是相机的可视角度范围</font>
+ <font style="color:rgb(25, 27, 31);">FOV=2arctan（h/2f）其中h为传感器高度，f为焦距</font>
+ <font style="color:rgb(25, 27, 31);">因此视场与传感器大小、焦距均有关</font>
+ <font style="color:rgb(25, 27, 31);">手机摄像头通过同时减少焦距和传感器大小以求得到和相机类似的FOV</font>

### **<font style="color:rgb(25, 27, 31);">曝光</font>**
+ <font style="color:rgb(25, 27, 31);">Exposure = time * irradiance，曝光=时间*Irradiance</font>
+ <font style="color:rgb(25, 27, 31);">时间由快门控制，irradiance由光圈的大小和焦距控制</font>
+ <font style="color:rgb(25, 27, 31);">快门速度慢，曝光时间长，光在感光器上停留时间长，会产生运动模糊的现象</font>
+ <font style="color:rgb(25, 27, 31);">对于机械快门，如果拍摄高速物体会产生运动扭曲的现象</font>
+ <font style="color:rgb(25, 27, 31);">光圈的大小控制单位时间内的进光量，光圈可以制造景深，光圈越大景深越明显</font>
+ <font style="color:rgb(25, 27, 31);">通过F数（F/N）来描述光圈的大小，F数是焦距/光圈直径（N=f/D）</font>
+ <font style="color:rgb(25, 27, 31);">因此运动模糊和景深无法同时出现</font>
+ <font style="color:rgb(25, 27, 31);">ISO是一个后期的处理值通过乘上ISO来改变整体的明暗</font>
+ <font style="color:rgb(25, 27, 31);">ISO也可以在硬件上进行改变，比如改变感光器的灵敏度</font>
+ <font style="color:rgb(25, 27, 31);">ISO过大会产生噪声，因此一般不直接大范围调整ISO来提高亮度</font>
+ <font style="color:rgb(25, 27, 31);">通过很长的曝光时间应用于延时摄影上</font>

### **<font style="color:rgb(25, 27, 31);">镜头（透镜）</font>**
+ <font style="color:rgb(25, 27, 31);">真实的透镜是由很多块玻璃叠在一起制作而成的</font>
+ <font style="color:rgb(25, 27, 31);">薄透镜对于平行光会集中在一个点，被称之为焦点</font>
+ <font style="color:rgb(25, 27, 31);">目前的相机通过多块透镜的组合可以制作出不同的焦距</font>
+ <font style="color:rgb(25, 27, 31);">课程中我们考虑的是理想的薄透镜，同时可以任意改变焦距</font>
+ <font style="color:rgb(25, 27, 31);">物距、相距、焦距之间的关系：1/f=（1/zi）+（1/z0）其中f为焦距，zi为相距，z0为物距</font>
+ <font style="color:rgb(25, 27, 31);">在焦点前后，光线开始聚集和扩散，点的影象变成模糊的，形成一个扩大的圆，这个圆就叫做CoC</font>
+ <font style="color:rgb(25, 27, 31);">离焦模糊是在拍照时，被摄物体不在焦点，使得成像不是清晰的一个点，而是变成coc，coc随着光圈的增加而增大。</font>
+ <font style="color:rgb(25, 27, 31);">coc的宽度：C/A=d'/zi=|zs-zi|/zi</font>
+ <font style="color:rgb(25, 27, 31);">其中zs为透镜到coc的距离，A为镜头的直径，d'为zs-zi的绝对值</font>

### **<font style="color:rgb(25, 27, 31);">流体模拟</font>**
### **<font style="color:rgb(25, 27, 31);">定义</font>**
+ <font style="color:rgb(25, 27, 31);">水体是由多个刚体小球形成的，不可压缩</font>
+ <font style="color:rgb(25, 27, 31);">模拟与渲染是分开的过程</font>

### **<font style="color:rgb(25, 27, 31);">实现思路</font>**
+ <font style="color:rgb(25, 27, 31);">通过获取任意时刻小球的分布位置来获取小球单位面积的密度</font>
+ <font style="color:rgb(25, 27, 31);">如果密度如果发生改变（不同于平静的水面），就通过通过改变小球的位置来修正位置，让水总有一个趋于平静的趋势</font>
+ <font style="color:rgb(25, 27, 31);">通过加入能量损失让水最终停下来</font>

### **<font style="color:rgb(25, 27, 31);">质点法和网格法</font>**
<font style="color:rgb(25, 27, 31);">质点法和网格法流体模拟中的两个不同的思路</font>

<font style="color:rgb(25, 27, 31);">质点法（拉格朗日法）：逐个模拟每个粒子</font>

<font style="color:rgb(25, 27, 31);">网格法（欧拉方法）：将一个空间定义为一个网格，通过观察以网格为单位的时间如何变换来模拟</font>

### **<font style="color:rgb(25, 27, 31);">混合方法MPM</font>**
+ <font style="color:rgb(25, 27, 31);">质点：将不同的粒子的不同属性储存在粒子上</font>
+ <font style="color:rgb(25, 27, 31);">网格：模拟变换的过程在网格中完成</font>
+ <font style="color:rgb(25, 27, 31);">将每一个时刻网格的信息写回网格内的粒子上</font>
